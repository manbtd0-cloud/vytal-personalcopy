# Vytal Reference-Driven Redesign — Final Execution Locks

**Status:** Highest-priority implementation locks. These decisions override any earlier optional or exploratory wording in companion specs/plans.

## 1. H13 color field is fixed

Home chapter H13 (`concrete-value`) is a **full Warm Ivory field with Ivory Ink text**.

Do not implement H13 as a split dark/light field and do not reopen this choice during implementation.

Final Home color sequence for the last chapters is therefore:

- H12 Platform arc — Deep Ink
- H13 Concrete value — **Warm Ivory / Ivory Ink**
- H14 Final entry — **Deep Ink with resolved coral/mint Signal Thread**

The purpose is deliberate chapter contrast: H13 functions as the final calm explanatory reset before H14 returns to the dark cinematic register for conversion.

## 2. Typography is fixed for the whole baseline implementation

Use:

- **Poppins** for display/body
- **JetBrains Mono** for technical metadata, labels, indices and signal annotations

Do **not** introduce or prototype a new display font during Gate A, B, C or D.

Typography quality must be improved through:

- scale;
- line breaks;
- width constraints;
- weight;
- tracking;
- casing;
- alignment;
- whitespace;
- composition;

not by changing font families mid-build.

A future font experiment, if ever desired, is a separate post-implementation design task and is outside the canonical redesign plan.

## 3. Precedence

When companion documentation conflicts with these two locks, this file wins.

The canonical implementation sequence, route architecture, medical-claim rules, media-slot manifest, Signal Thread system, GSAP-only runtime, ReactBits restrictions and visual gates remain unchanged.
